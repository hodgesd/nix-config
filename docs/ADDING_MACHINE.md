# Adding a New Machine

This guide walks through adding a new machine to your Nix configuration.
The first sections cover a new Mac; see
[Adding a NixOS host](#adding-a-nixos-host-vm-or-server) at the end for
homelab machines.

## Step 1: Add Machine Metadata

Edit `lib/machines.nix` and add your machine's metadata. The hostname is
derived from the attribute name — don't repeat it inside the entry:

```nix
# lib/machines.nix
{
  # ... existing machines ...

  newmachine = {
    type = "darwin";
    chip = "m4-pro";  # CPU/chip type (optional — omit for VMs)
    formFactor = "laptop";  # "laptop", "desktop", "server", or "vm"
    primaryUse = "development";  # "development", "server", etc.
    # username = "someotheruser";  # Optional — defaults to "hodgesd"
    specs = {
      ram = "32GB";
      storage = "2TB";
      cpu = 14;
      gpu = 20;
    };
    screen = "16\"";  # Optional, for laptops
  };
}
```

## Step 2: Create Host Directory

```bash
mkdir -p hosts/darwin/newmachine
```

Create `hosts/darwin/newmachine/default.nix`:

```nix
{ ... }:
{
  # Add any machine-specific configuration here
  # For example:
  # homebrew.casks = [ "specific-app" ];
}
```

## Step 3: Add to flake.nix

Edit `flake.nix` and add your machine to `darwinConfigurations`:

```nix
# flake.nix
darwinConfigurations = {
  mbp = libx.mkDarwin {hostname = "mbp";};
  mini = libx.mkDarwin {hostname = "mini";};
  air = libx.mkDarwin {hostname = "air";};
  newmachine = libx.mkDarwin {hostname = "newmachine";};  # Add this
};
```

## Step 4: Set Machine Hostname

Before building, ensure your machine's hostname matches:

### macOS:

```bash
# Check current hostname
hostname -s

# Set hostname if needed
sudo scutil --set HostName newmachine
sudo scutil --set LocalHostName newmachine
sudo scutil --set ComputerName newmachine
```

Or use the provided script:

```bash
chmod +x scripts/set_mac_name.sh
./scripts/set_mac_name.sh
```

## Step 5: Build Configuration

```bash
# Check configuration is valid
nix flake check --no-build

# Build and activate
darwin-rebuild switch --flake .#newmachine
```

## Step 6: Customize

Now you can customize your machine-specific configuration:

- **Dock apps**: Edit `hosts/darwin/newmachine/default.nix`
- **Machine-specific packages**: Add to host's `default.nix`
- **Different system settings**: Override in host's `default.nix`

## Common Customizations

### Custom Dock Configuration

Instead of using a preset, define your own:

```nix
# hosts/darwin/newmachine/default.nix
{ ... }:
{
  system.defaults.dock.persistent-apps = [
    "/Applications/Safari.app"
    "/Applications/Mail.app"
    "/Applications/Obsidian.app"
  ];
}
```

### Machine-Specific Homebrew Apps

```nix
# hosts/darwin/newmachine/default.nix
{ ... }:
{
  homebrew.casks = [
    "machine-specific-app"
  ];
}
```

### Different System Defaults

```nix
# hosts/darwin/newmachine/default.nix
{ ... }:
{
  # Override common settings
  system.defaults.dock.autohide = true;
  system.defaults.dock.tilesize = 48;
}
```

### Use Machine Metadata

You can access machine metadata in your config:

```nix
# hosts/darwin/newmachine/default.nix
{ machine, pkgs, ... }:
{
  # Conditional based on machine properties
  environment.systemPackages = with pkgs;
    if machine.formFactor == "laptop" then
      [ powertop ]
    else
      [ ];
}
```

## Troubleshooting

### Configuration doesn't build

```bash
# Check for syntax errors
nix flake check

# Build with verbose output
darwin-rebuild switch --flake .#newmachine --show-trace
```

### Hostname mismatch

Ensure the hostname in:
1. `lib/machines.nix` (hostname field)
2. System hostname (`hostname -s`)
3. `flake.nix` (configuration name)

All match exactly.

### Missing packages

If packages are missing, check:
1. `hosts/common/common-packages.nix` - Cross-platform packages
2. `hosts/common/darwin/packages.nix` - Darwin-specific packages
3. Host-specific `default.nix` - Machine-specific packages

## Adding a NixOS host (VM or server)

1. **Registry entry** in `lib/machines.nix`:
   ```nix
   newvm = {
     type = "nixos";
     formFactor = "vm";  # or "server" for bare metal
     primaryUse = "homelab";
     # no chip needed for VMs
     specs = { ram = null; storage = null; cpu = null; gpu = null; };
   };
   ```
2. **Host directory** `hosts/nixos/newvm/` — unlike darwin hosts this is
   **required**. Minimum contents:
   - `hardware-configuration.nix` — copy verbatim from the machine
     (generated by `nixos-generate-config`)
   - `default.nix` — imports hardware config, sets
     `system.stateVersion` (the release it was installed with — never
     bump), boot loader, and any services
3. **Flake output** in `flake.nix`:
   ```nix
   nixosConfigurations = {
     # ...
     newvm = libx.mkNixos {hostname = "newvm";};
   };
   ```
4. **CI**: add the host to the eval matrix in
   `.github/workflows/eval.yaml` (and a build job in `build.yaml` if you
   want its closure in Cachix).
5. **Secrets (if needed)**: derive the host's age recipient
   (`ssh-keyscan -t ed25519 <host> | ssh-to-age`), add it to
   `.sops.yaml` with a creation rule for `secrets/newvm.yaml`, create
   the secrets file (`sops secrets/newvm.yaml`), and declare
   `sops.secrets.*` in the host config.
6. **Deploy**: `just deploy newvm dry-activate <ssh-dest>` then
   `just deploy newvm switch <ssh-dest>` — or on the machine itself,
   `sudo nixos-rebuild switch --flake .#newvm`.

The server baseline (`hosts/common/nixos-common.nix`) gives every NixOS
host tailscale (+SSH), docker, openssh with your LAN key, a
tailnet-only firewall, and the Cachix substituter for free.
